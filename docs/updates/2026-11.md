## U-20261115-01 · 2026-11-15 · Navigation as a side bar view of JEditor's new shell · #migration #ui #jeditor

- **Why**: JEditor's window gets an activity bar, a side bar, a bottom panel and a secondary side bar, and themes of its own (JEditor `feat/modern-shell-ui`, its U-20261115-01). PyBreeze's window is that window, so the navigation dock at the left ended up beside the side bar: two columns before the editor.
- **What**: the tree and its search box are `NavigationPanel`; with a JEditor whose window has a shell, `PyBreezeMainWindow` adds it as the side bar view `pybreeze_navigation` (`workbench.add_view`, icon `navigation`, title from `navigation_dock_title`), which gives it an activity bar icon and a View menu entry. JEditor restores its layout before the view exists, so it is restored again afterwards; on a first start the navigation is the view shown. `NavigationDock` wraps the same panel for a JEditor without a shell, with its Dock menu entry and remembered visibility unchanged. `start_editor(theme=...)` takes JEditor's own themes as well, and the fallback when `startup_setting()` fails goes through `EditorMain.apply_style()` where there is one.
- **Files**: `pybreeze/pybreeze_ui/navigation/navigation_dock.py`, `pybreeze/pybreeze_ui/editor_main/main_ui.py`, `test/test_utils/test_navigation.py`, `test/test_utils/test_start_theme.py`, the three READMEs, `architecture.md`, `architecture_explore.md`.
- **Evidence**: `test_navigation.py` and `test_start_theme.py` pass against JEditor `feat/modern-shell-ui` (side bar tests run, dock tests skipped) and against the installed JEditor 1.0.25 (the reverse).
- **Open items**: `progress.md` #150.
